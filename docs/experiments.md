# 优化历程

默认保留平台验证过的 BR5，避免把“编号更新”误当作“性能更好”。下表是历史实验摘要，不是本次重新测试结果；未纳入默认源码的实验也不在此仓库提供可构建版本。

| 版本 | 尝试 | 结果 / 决策 |
| --- | --- | --- |
| BR2 | 前期基线 | 平台 2/2 PASS，7.72 / 5.78 μs |
| BR3 | Axpy | 正确性通过，混合性能回退，不采用 |
| BR4 | 固定 n 模板特化 | 正确性通过，代码体积增加且 n=6 变慢，不采用 |
| BR5 | 批量归约尾段 mask | 平台 2/2 PASS，7.60 / 5.66 μs；作为默认版本 |
| BR6 / BR7 | Gather / Brcb 聚合 hIn | 正确性通过，混合性能回退，不采用 |
| BR8 | 向量化 RMS | 正确性通过，混合性能回退，不采用 |
| BR9 | 扩大 paired-token 路径 | 小 token 场景回退 |
| BR10 | 收窄 paired-token 路径 | 平台 2/2 PASS，但 8.50 / 5.82 μs 比 BR5 慢，不采用 |
| BR11 | packed sigmoid | 382 组正确性通过，复测收益不一致，未提交 |
| BR12 | bias 批量搬运 | 382 初始 / 308 回放检查通过；部分中等 shape 快约 4–11%，小 shape 慢约 2–3%；没有已确认平台结果 |
| BR13 | 首段输入预取 | 仅实验源码，未完成编译及 NPU 验证，不发布为可提交版本 |

## BR5 的核心变化

基于 BR2，只拓展 resident 批量点积的尾段处理，不叠加 BR3/BR4。

批量行路径由 `nD % 64 == 0` 放宽至 `nD % 8 == 0`，归约槽位预算取 `ceil(nD/64)`。完整 64 元素段维持原流程，尾段的乘法和 WholeReduceSum 使用有效元素 mask。D 非 16 对齐仍走原流式分支。

n=6 的部分尾段 shape 明显受益，但不应外推到所有输入：D=16/S=32 的复测延迟下降约 18.8–19.4%；D=48 专项约 23–30%，后者只做过一轮候选/基线对照，不是多轮统计结论。

## 经验

- 固定 shape 特化可能增加指令体积；少量操作的“向量化”也可能被搬运与同步成本抵消。
- 大 shape 的收益不能掩盖小 shape 回退，应逐 shape 看数据。
- 正确性通过不等于性能通过；自建测量与平台隐藏测试也不是同一套指标。
- 单次平台超时不足以认定 kernel 回归，应结合复提与实机日志排查。
